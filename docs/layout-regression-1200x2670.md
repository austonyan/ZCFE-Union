# 1200×2670 竖屏布局回归

## 目标与复现口径

用户给出的屏幕规格为 2670×1200，已确认实际以手机竖屏使用，因此按宽 1200、高 2670 像素测试，而不是横屏窗口。

像素分辨率不能唯一决定 Compose 的可用宽度。本轮覆盖 480 / 540 / 600dpi，约为 400 / 356 / 320dp，并分别检查常规字号与 1.4 倍字号。没有按某个手机型号或像素宽度硬编码布局。

设备为 MuMu Android 15。测试期间覆盖安装，不卸载或清空应用数据；完成后恢复原分辨率、密度和字号。

## 已确认的问题与修复

- 预约卡片中，主按钮使用 `weight(1f)`，右侧取消操作先占宽；在 356dp / 1.4 倍字号下，真实 `ReservationCard` 的“启动设备”被挤成两行，已截图确认。
- 新增 `PrismActionRow`：不足时让整个操作换行，不压缩按钮文字。预约、充值/用量、凭证操作及设备状态标签使用这一布局；关键动作标签明确为单行。
- 弹窗不再强制将任意长确认文字塞进半宽按钮。按实际字阶、字号和内容宽度测量；不足时两按钮上下等宽排列，保持原确认/取消回调顺序。
- `PrismSegmented` 依照实际文本测量，在等分列无法容纳完整标签时切换为纵向连接分组；不缩小字号，不裁掉关键选项。
- “回到本周”从固定 88dp 槽改为按实际文字宽度加内边距确定槽宽，当前周与非当前周仍保留同一槽位，避免切周跳宽。
- 整页截图补充发现：320dp / 1.4 倍字号下，欢迎页三个平台说明块的图标会挤掉标签第二个字，改为上下排列图标与文字；“我的”三套账号说明允许按内容增长，不再被状态徽标挤成两行省略。

## 自动化证据

`app/src/androidTest/java/com/union/campus/TargetResolutionLayoutTest.kt`：6 种尺寸/字号组合 × 4 类实际组件，共 24 项通过。

覆盖预约动作、长确认动作、分段选择、非当前周的周切换。验证完整标签单行、未省略、没有垂直裁切或超过 1 个取整像素的水平溢出，且可见行末覆盖完整文本。

测试使用与生产相同的组件及独立的本地布局数据，不会调用设备预约、开关、取消等写接口。测试 Activity 显式保持竖屏；`LocalDensity` 模拟三种逻辑宽度和字号，整页截图另用真实系统 density/font_scale 设置覆盖。

注意：`TextLayoutResult.didOverflowWidth` 对某些分数字宽与整数布局边界也会报告 true，因此没有直接把这一标志当作裁切证据；检查实际行宽、行末索引、行数与省略状态，并结合截图确认。
